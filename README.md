# 票准 TaxSure

> 中小企业发票合规 AI 审计官 —— 报税前，先让 AI 把每一张发票过一遍。
>
> **AI 不算数，AI 只找依据。** 每一个数字都可复算，每一句结论都能翻到原文。

一个面向中小企业的发票合规自查工具。三个能力：

| 能力 | 做什么 |
| --- | --- |
| 发票体检 | 上传台账，逐行比对你可能被税务系统比对出来的问题（8 类规则），每条附法规依据与整改建议 |
| 税费试算 | 小规模 / 一般纳税人分流，算增值税、附加税、小微所得税、印花税，并提示 30 万免征线的跳档风险 |
| 政策问答 | 用大白话提问，BM25 检索法规库并给出带文号、条款的答案；检索不到就拒答，不编 |

## 快速开始

```bash
python run.py                 # 默认 http://127.0.0.1:8848
python tests/smoke_test.py    # 离线回归，28 项（不需要网络）
python tests/llm_live_test.py # 在线实测，14 项（需要 API Key）
```

不需要装依赖：服务、检索、计算全部用 Python 标准库实现，只有读 Excel 时用到 `pandas` / `openpyxl`。
**没有 API Key 也能完整跑** —— 自动进入模板模式，三套功能一个不少。

## 可选：接入大模型

**方式一（推荐）：** 把 `.env.example` 复制成 `.env`，填上 Key，然后直接 `python run.py`。

```bash
copy .env.example .env
# 编辑 .env，填入 TAXSURE_API_KEY
python run.py
```

**方式二：** 用环境变量（优先级高于 .env，适合临时切换）。

```bash
set TAXSURE_API_BASE=https://api.deepseek.com/v1
set TAXSURE_API_KEY=sk-***
set TAXSURE_MODEL=deepseek-chat
python run.py
```

兼容任何 OpenAI 协议的服务（DeepSeek / 通义 / 智谱 / 本地 vLLM）。
不配置时模型相关能力自动降级，三个功能不中断。

> 已用 `deepseek-chat` 实测：4 个问题均正确命中条文，端到端延迟 2.2–2.7 秒，
> 结果见报告第八章「接入真实模型后的实测」。

## 设计原则

1. **AI 不碰算术。** 税额由 `app/rules.py` 的确定性规则计算，输出可逐行核对（项目/依据/税率/金额/说明/法规号）。
2. **AI 不碰事实。** 所有法规表述来自 `data/regulations.jsonl` 的检索结果，模型无权新增条文。
3. **不知道就说不知道。** 检索得分低于阈值直接拒答，并告诉用户还缺哪几条信息。
4. **可解释优先。** 用 BM25 而不是向量库：27 条法规的规模下，BM25 确定、可打印、零依赖，评委能现场验证为什么召回这一条。
5. **可评测。** 28 项自测覆盖问答命中、拒答、8 类发票规则、4 组税额边界，改完代码一键复跑。

## 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/health` | 法规库条数、模型是否接入 |
| GET | `/api/regs` | 全部法规 |
| GET | `/api/sample` | 内置样例台账（9 行，埋了 6 类问题） |
| POST | `/api/ask` | `{question}` → 意图、参数、试算、回答、引用、命中条文 |
| POST | `/api/audit` | 台账行或文件流 → 风险分 + 问题清单 |
| POST | `/api/calc` | `{params}` → 税额明细 + 合计 + 待确认项 |

## 法规库维护

每条法规是一个 JSON 对象，关键字段：

```json
{"id": "R01", "title": "小规模纳税人月销售额10万元以下免征增值税",
 "doc_no": "财政部 税务总局公告2023年第19号", "article": "第一条",
 "effective": "2023-01-01", "until": "2027-12-31",
 "text": "……原文……", "conclusion": "……一句人话结论……",
 "tags": ["增值税", "小规模", "免税"], "kw": "小规模 免税 10万"}
```

政策变化时只改一行 JSON，不需要重训模型，也不需要改代码。

> **注意**：条文与文号在提交/上线前应由财税背景的同学对照官方原文复核一遍。
> 产品设计上把"人工校对"当成必要环节——这也是我们不同于通用助手的地方。
